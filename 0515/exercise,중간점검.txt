중간점검 (370p ~ 394p)
1장. 객체지향의 기본 개념
1-1: 객체 지향 프로그래밍은 독립적인 단위인 '객체'들을 서로 유기적으로 조합하여 하나의 프로그램을 완성해 나가는 개발 기법입니다.

1-2: 가장 대표적인 단점으로는 초기 설계 단계가 비교적 복잡하여 시간이 오래 걸린다는 점과, 실행 속도가 상대적으로 느릴 수 있다는 점입니다.

1-3: 서로 밀접하게 연관된 데이터(속성)와 그 데이터를 처리하는 기능(메서드)을 하나의 독립된 주머니(캡슐) 안에 안전하게 묶어 보호하는 것을 뜻합니다.

1-4: 구체적인 객체를 생성하기 위해 필요한 변수들과 메서드들을 미리 정의해 놓은 설계도이자 틀입니다.

1-5: 클래스라는 설계도를 바탕으로 실체화되어, 컴퓨터 메모리 공간에 실제로 생성되고 물리적으로 동작하는 구체적인 실체입니다.

1-6: 클래스는 개념을 정의한 추상적인 데이터 타입인 반면, 인스턴스는 그 내용을 바탕으로 메모리에 실체화된 구체적인 대상이라는 점에서 차이가 있습니다.

2장. 클래스 구현과 사용
2-1: 파이썬에서는 class라는 키워드를 선언하여 정의합니다.

2-2: 보통 첫 글자를 대문자로 시작하고 단어가 바뀔 때마다 대문자로 구분하는 파스칼 케이스(PascalCase, 또는 어퍼 카멜 케이스) 방식을 사용합니다.

2-3: 클래스 이름 뒤에 소괄호 ()를 붙여서, 마치 일반 함수를 호출하는 것과 같은 방식으로 인스턴스를 생성합니다.

2-4: 마침표 기호인 점(.) 연산자를 활용하여 내부 멤버에 접근합니다.

2-5: 클래스 내부에 선언되어 특정 객체의 행동이나 기능을 수행하는 함수를 메서드라고 부릅니다.

2-6: self는 현재 해당 메서드가 호출되어 실행되고 있는 '인스턴스 자기 자신'의 메모리 주소를 가리키는 변수입니다.

2-7: 객체가 생성될 때 가장 먼저 자동으로 실행되어 초기화를 담당하는 '생성자'라고 불리는 특별한 메서드입니다.

3장. 정보 은닉과 캡슐화
3-1: 클래스 내부의 중요한 데이터를 외부에서 무분별하게 직접 수정하거나 접근하지 못하도록 보호하는 안전장치입니다.

3-2: 외부 접근이 차단된(은닉된) 변수의 값을 안전하게 읽어오거나 변경할 수 있도록 통로 역할을 해주는 메서드(Getter/Setter)입니다.

3-3: 외부에 노출하고 싶지 않은 변수의 이름 앞에 언더바(밑줄) 두 개(__)를 연속으로 붙여주면 비공개(Private) 상태로 지정할 수 있습니다.

4장. 객체와 참조
4-1: 객체 자체가 복사되는 것이 아니라, 원본 객체가 위치한 메모리 상의 주소값(참조값)이 전달됩니다.

4-2: 새로운 텔레비전 객체가 하나 더 복사되는 것이 결코 아닙니다. 컴퓨터 메모리 공간 어딘가에 [채널 11, 볼륨 10, 전원 True]라는 상태를 가진 실제 인스턴스는 오직 1개만 생성되며, 새로운 변수에는 그 객체의 메모리 주소(참조값)만 똑같이 복사되어 같은 실체를 가리키게 됩니다.

5장. 인스턴스 변수와 클래스 변수
5-1: 인스턴스 변수는 각각의 객체들이 독립적으로 가지는 고유한 값이고, 클래스 변수는 클래스 전체가 소유하여 해당 클래스로 생성된 모든 인스턴스들이 동일한 값을 공유하는 변수입니다.

5-2: 클래스 내부 영역이되, 정의된 모든 메서드들의 바깥쪽에 변수를 선언하기만 하면 자동으로 클래스 변수로 취급됩니다.

6장. 특수 메서드
6-1: 객체의 정보를 사용자가 읽기 편한 직관적인 문자열 형태로 변환하여 출력해야 할 때 자동으로 호출되는 메서드입니다.

6-2: 인스턴스 간의 값이 같은지 동등성 비교를 수행하려면 클래스 내부에 __eq__(self, other) 메서드를 따로 구현해 주어야 합니다.
